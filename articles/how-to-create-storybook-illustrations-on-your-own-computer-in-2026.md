You might be making a bedtime story, testing a picture-book idea, or illustrating a short piece you wrote. Start with a small set of scenes. Once the apps and models are ready, the local workflow can run without internet.

## What can you make with this workflow?

You can create individual story illustrations in a chat and refine the prompts as the story develops. A local text model helps describe the scenes. A local image model turns those descriptions into pictures. The resulting images stay available with the conversation.

Useful first projects include:

- A single illustration for a story you already wrote.
- Three scenes that show a beginning, a problem, and a resolution.
- A character study before you commit to a longer book.
- Alternative settings or color palettes for the same premise.

This guide focuses on illustrations. A print-ready book also needs page layout, typography, and a check of the final output. Keep readable story text in your document instead of depending on an image model to draw accurate lettering inside the art.

## Start with a story small enough to finish

Choose one character, one place, and one simple problem. That gives you a clear way to judge whether the pictures belong together. A vague request for an entire book gives the models more decisions to make before you have chosen a visual direction.

For example:

> A small fox with a blue scarf finds a lost paper boat beside a garden pond. The fox tries to return it before the rain begins. The story is gentle, cheerful, and suitable for young children.

Ask the local chat model:

> Turn this idea into three illustration briefs: discovery, a small setback, and a happy ending. Keep the fox's blue scarf and the garden pond in every scene. Describe the pictures, not text printed inside them.

Read the briefs before generating. Does each scene add something? Can you describe the change between the first picture and the last? Revise the story at this stage, when a small text change is enough.

## How do you keep the pictures visually related?

Write a short character and style description, then repeat it in each image prompt. Name the features that must stay stable: clothing, colors, proportions, setting, and medium. This gives the image model consistent guidance across requests.

For the fox story, a reusable description could be:

> Small orange fox, cream muzzle, short blue scarf, rounded shapes, watercolor storybook illustration, soft green garden, warm natural light, no lettering.

Then add the scene-specific action:

> The fox leans over the edge of a pond and notices a yellow paper boat beside a lily leaf. Wide view with the fox on the left and the boat clearly visible on the right.

This is a prompt recipe, not a guarantee of identical characters. Compare the ears, scarf, face, and scale in every result. If a detail changes, revise the prompt and generate another option before building the rest of the sequence around it.

A reference image can help when the selected image model supports image-to-image work. Use it to guide the next picture, while checking the result rather than assuming exact identity preservation.

## Give every illustration a job

A useful story illustration shows one clear moment. Decide what the reader should notice first, and keep secondary details from hiding it. You can ask the local assistant to improve that focus before spending time on another generation.

| Story moment | What the picture should communicate |
|---|---|
| Discovery | The fox notices something unexpected |
| Setback | The boat is harder to reach than expected |
| Resolution | The boat reaches its owner |

Try an editing request such as:

> Make the boat easier to notice. Keep the fox and setting unchanged in the description. Remove background details that compete with the main action.

Read the revised prompt. If it introduces a new character or changes the setting, correct it. You are directing the story; the assistant helps express the picture you want.

## Getting started in OGAD

Download a local chat model and an image model in **Models**. Choose both, open a new chat for the story, and prepare the three scene briefs. Then ask for the first image using the finished visual description.

1. Install [OGAD](https://getoffgridai.co/desktop/) and download models that fit your computer.
2. Test a short chat reply, then a simple image request.
3. Start a story conversation and write the character and style description.
4. Generate one illustration and inspect it at a useful size.
5. Keep the description that works and use it for the next scene.

Use the image-generation option when you want a picture rather than another prose description. The chat can show the generated result, with generation metadata such as model, dimensions, steps, and seed when available.

This uses the core local chat and image workflow in [OGAD 0.0.51](https://github.com/off-grid-ai/OGAD/releases/tag/v0.0.51). Download the models before going offline. Leave remote model settings off for requests you intend to process entirely on the computer.

## What should you check before using the artwork?

Review each picture against the story rather than only asking whether it looks attractive. A beautiful image that changes the character or reveals the ending too early may not serve the page.

Check these details:

- Does the image show the right action?
- Is the main object easy to find?
- Are recurring clothing and colors consistent?
- Does the mood fit the intended reader?
- Is there space for the page's text if you will add it later?

If generation fails, try a model and image size your computer can handle. If the result is wrong, change one part of the prompt at a time. Keep a successful version before trying a new direction.
